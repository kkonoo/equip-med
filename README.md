# 공동기기@KNUmed (equip-med)

여러 연구실이 같이 쓰는 공동기기를 예약하고 기기별 매뉴얼을 보는 웹앱(PWA)이에요. 구글 계정으로 로그인해 가입 신청을 하고, 총관리자가 승인하면 쓸 수 있어요. 설치 없이 브라우저에서 열고, 폰에서는 홈 화면에 추가해 앱처럼 써요.

**주소: https://kkonoo.github.io/equip-med/** · 관리자 페이지: https://kkonoo.github.io/equip-med/admin.html

## 사용자 화면

| 탭 | 하는 일 |
|---|---|
| 예약 | 기기를 고르면 주간 그리드(가로 요일, 세로 시간)가 나와요. 폰(900px 이하)에서는 하루 보기. 빈 칸을 누르면 예약 창이 열리고(시작·종료를 누른 칸으로 미리 채움, 밤샘은 종료 날짜를 바꿔서), 다른 사람 예약을 누르면 이름·연구실·시간이 보여요. 승인된 예약은 회색, 승인 대기는 점선, 내 예약은 크림슨, 점검·고장 기간은 빗금, 예약할 수 없는 시간은 옅은 회색이에요 |
| 내 예약 | 다가오는 예약과 지난 예약. 상태(승인 대기 · 승인 · 거절+사유 · 취소), 시작 전엔 취소, 끝난 예약엔 **사용일지 쓰기**(실제 시작·종료, 특이사항, 문제 있었음)와 미작성 표시 |
| 기기 | 기기 카드(사진, 이름, 위치, 상태, 담당자, 승인 필요 여부, 교육이 필요한 기기는 🎓 교육 필요 / 교육 받음). 위치의 첫 단어(호수)가 같은 기기끼리 묶여 보여요(N호수 오름차순 → 343호 같은 다른 호수 → 호수 없는 곳, 묶음 안은 기기 이름 abc순). 예약 탭의 기기 고르기도 같은 묶음이에요. 누르면 매뉴얼 본문, 링크(구글 드라이브의 PDF·사진), 예약 규칙이 나오고 바로 **예약하기**로 넘어가요 |

기기 담당자나 총관리자로 로그인하면 위에 **관리자 페이지** 링크가 보이고, 처리할 승인 대기 건수가 배지로 떠요. 오른쪽 위 동그라미(이름 첫 글자)를 누르면 이름 수정, 언어, 테마, 글씨 크기, 로그아웃이 있어요.

### English

외국인 대학원생을 위해 사용자 화면(로그인 · 가입 신청 · 예약 · 내 예약 · 기기 · 설정)은 **한국어 / English**로 바꿀 수 있어요. 처음엔 브라우저 언어를 따르고(한국어가 아니면 English), 로그인 화면 아래나 설정 → 화면 → 언어에서 바꿔요. 영어 이름은 'Shared Equipment@KNUmed'예요.

- 관리자 페이지는 한국어로만 보여요.
- 기기 이름 · 위치 · 매뉴얼 · 연구실 이름 · 거절 사유처럼 사람이 적은 내용은 적은 그대로 보여요. 외국인 학생이 쓰는 기기는 이름이나 매뉴얼에 영어를 같이 적어 두면 좋아요 (예: '공초점 현미경 (Confocal) LSM 900').
- 화면 문장은 [`js/i18n.js`](js/i18n.js)에 한국어 문장 → 영어로 모여 있어요. 화면에 새 문장을 넣으면 `t('한국어 문장')`으로 감싸고 여기에 영어를 더해요 (빠지면 한국어 그대로 보여요).

## 관리자 페이지 (admin.html)

담당자와 총관리자만 열 수 있어요. 담당자는 자기 담당 기기만 봐요.

| 탭 | 하는 일 | 보는 사람 |
|---|---|---|
| 예약 승인 | 승인 대기 목록, 승인 · 거절(사유), 같은 시간에 겹치는 신청 경고, 점검·고장 기간에 잡힌 예약 경고, 교육이 필요한 기기인데 교육 기록이 없는 사람의 예약 경고와 **🎓 교육 완료** 버튼, 다가오는 예약을 사유를 적고 취소 | 담당자, 총관리자 |
| 가입 승인 | 가입 신청 승인(연구실 고르기 또는 직접 입력한 이름으로 새 연구실) · 거절, 사용자 목록에서 연구실 · 역할 · 사용 중(비활성화) 바꾸기 | 총관리자 |
| 기기 | 기기 추가 · 수정 · 삭제(목록에서 바로), 사진 올리기 · 빼기(긴 쪽 1024px로 줄여서), 담당자 지정, 승인 필요 여부, 교육 필요 여부와 교육 받은 사람(추가는 총관리자, 지우기는 담당자도), 예약 규칙 · 예약 참고, 상태(정상/점검/고장 + 사유 · 언제까지), 매뉴얼 · 링크. 목록은 사용자 화면과 같은 순서 | 총관리자 전체, 담당자는 담당 기기(이름 · 위치 · 담당자 제외) |
| 사용일지 | 기기별 일지 목록('문제 있었음'은 위로), 사용일지가 없는 지난 예약 | 담당자, 총관리자 |
| 통계 | 월을 고르면 연구실 × 기기 사용 시간 표. 칸마다 합계와 '일지 · 예약'으로 나눠 보여 줘요 | 총관리자, 담당자는 담당 기기만 |
| 연구실 | 연구실 추가 · 이름 수정 · 순서, 가입 때 직접 입력된 연구실 정리 | 총관리자 |
| 데이터 | 전체 백업 파일 저장(JSON) | 총관리자 |

## 예약 규칙과 흐름

- 기기마다 **승인 필요**를 켜고 끌 수 있어요. 새 기기는 승인 필요가 기본값이에요. 승인 필요 기기는 '신청' → 담당자가 승인하면 확정, 아니면 '예약'하자마자 확정이에요.
- 승인 대기와 승인됨은 둘 다 그 시간을 차지하고, 거절되거나 취소되면 시간이 풀려요. 본인은 시작 전까지 취소할 수 있고, 담당자와 총관리자는 언제든 사유를 적고 취소할 수 있어요.
- 기기별 예약 규칙: **예약 단위**(기본 30분, 그리드 칸 크기), **1회 최대 시간**, **며칠 앞까지**(오늘부터 N일 뒤까지), **예약 가능 시간대**. 비워 두면 제한 없음이에요. **예약 참고**(한 줄에 하나씩, 예: '주말·공휴일 불가')는 예약 규칙 아래에 그대로 보여요.
- **교육 기록**: '처음 쓰는 사람은 교육 필요'로 정한 기기는 교육 받은 사람을 기록해요. 예약을 막지는 않고, 교육 기록이 없는 사람의 예약에 경고가 떠요. 담당자 · 총관리자가 예약 승인 탭에서 **🎓 교육 완료**를 누르거나, 총관리자가 기기 수정 창에서 사람을 골라 표시해요. 사용자는 기기 카드와 예약 창에서 자기 교육 여부를 보고, 총관리자는 사용자 목록의 '교육 받은 기기'에서 사람마다 봐요.
- **점검·고장**: 지금부터 '언제까지'까지 새 예약을 받지 않아요(그 뒤 날짜는 받아요). 끝을 비우면 정상으로 바꿀 때까지 막혀요. 이미 잡힌 예약은 자동으로 취소하지 않고 예약 승인 탭에 경고로 보여요.
- **겹침**: 저장하기 전에 같은 기기의 승인 대기 · 승인된 예약과 겹치는지 확인하고 막아요. 두 사람이 거의 동시에 같은 칸을 신청하면 둘 다 들어갈 수 있어요. 승인 필요 기기는 담당자 화면에 겹침 경고가 떠서 거기서 정리해요. 승인이 필요 없는 기기에서는 이 경우가 그대로 남아요(첫 버전의 알려진 한계).
- **사용 목적**은 본인 · 담당자 · 총관리자 화면에만 보여요. 다만 Firestore는 필드 단위로 숨길 수 없어서, 승인된 사용자라면 개발자 도구로 읽을 수는 있어요. 민감한 내용은 적지 않게 안내해 주세요.
- **통계**의 사용 시간은 사용일지가 있으면 실제 시간(일지), 없으면 승인된 예약 시간(예약)으로 세요. 끝난 예약만, 예약이 시작한 달 기준이에요.

## 처음 쓸 때

1. [Firebase 콘솔](https://console.firebase.google.com)에서 새 프로젝트를 만들어요.
2. **Authentication → 로그인 방법 → Google**과 **이메일/비밀번호**를 켜고(이메일 링크는 끔), **설정 → 승인된 도메인**에 `kkonoo.github.io`를 넣어요. 인증 · 비밀번호 메일은 앱 언어(한국어/English)로 가요.
3. **Firestore Database**를 만들어요 (위치는 `asia-northeast3` 서울 추천).
4. **Firestore → 규칙**에 [`firestore.rules`](firestore.rules) 내용을 그대로 붙여 넣고 게시해요.
5. **Firestore → 색인 → 복합**에 아래 두 개를 만들어요 ([`firestore.indexes.json`](firestore.indexes.json)과 같아요). 안 만들면 그리드·통계가 안 열리고, 브라우저 콘솔 오류에 나오는 링크를 눌러도 만들 수 있어요.
   - 컬렉션 `bookings`: `equipId` 오름차순 + `end` 오름차순 (예약 그리드, 겹침 확인, 관리자 승인 목록) — [바로 만들기](https://console.firebase.google.com/v1/r/project/equip-knumed/firestore/indexes?create_composite=Ck1wcm9qZWN0cy9lcXVpcC1rbnVtZWQvZGF0YWJhc2VzLyhkZWZhdWx0KS9jb2xsZWN0aW9uR3JvdXBzL2Jvb2tpbmdzL2luZGV4ZXMvXxABGgsKB2VxdWlwSWQQARoHCgNlbmQQARoMCghfX25hbWVfXxAB)
   - 컬렉션 `bookings`: `equipId` 오름차순 + `start` 오름차순 (통계) — [바로 만들기](https://console.firebase.google.com/v1/r/project/equip-knumed/firestore/indexes?create_composite=Ck1wcm9qZWN0cy9lcXVpcC1rbnVtZWQvZGF0YWJhc2VzLyhkZWZhdWx0KS9jb2xsZWN0aW9uR3JvdXBzL2Jvb2tpbmdzL2luZGV4ZXMvXxABGgsKB2VxdWlwSWQQARoJCgVzdGFydBABGgwKCF9fbmFtZV9fEAE=)
   - 쿼리 범위는 **컬렉션**(컬렉션 그룹 아님)이에요. 만든 뒤 '사용 설정됨'이 될 때까지 몇 분 걸리고, 그동안은 예약 화면에 '데이터 색인이 아직 없거나 만드는 중' 안내가 떠요.
6. **프로젝트 설정 → 내 앱 → 웹 앱 추가**에서 나온 `firebaseConfig` 값을 [`js/firebase-config.js`](js/firebase-config.js)에 넣고 main에 올려요. 값이 `null`이면 '설정이 필요해요' 안내만 보여요. (이 값은 공개돼도 괜찮아요. 데이터 보호는 보안 규칙이 해요.)
7. 앱에서 구글로 로그인해 **가입 신청**을 해요. 그다음 Firebase 콘솔 **Firestore → 데이터 → `users` → 내 문서**에서 `role`을 `admin`으로 바꾸면 첫 총관리자가 돼요.
8. 관리자 페이지에서 **연구실**을 추가하고, **기기**를 추가해 담당자 · 예약 규칙 · 매뉴얼을 넣어요. 이후 가입 신청은 가입 승인 탭에서 처리해요.
   - 동인동 공동기기(의대 연구기기현황 52개)는 한 번에 넣을 수 있어요: 관리자 페이지를 총관리자로 열고 F12 → Console에 `await import('./tools/import-dongin.js')`를 입력해요. 이미 있는 이름은 건너뛰어요. 담당자는 비어 있으니 들어간 뒤 기기 탭에서 지정해요. 매뉴얼은 설명 · 모델 · 이용 방법 · 문의(공동기기실 연락처)이고, 링크는 의대 홈페이지의 그 기기 페이지예요. 사진은 의대 홈페이지 사진(50개, 2개는 홈페이지에 없음)이 들어가요. 이용 방법에 '교육'이 있는 9개는 '교육 필요'로, 예약할 때 알아야 할 것(오퍼레이터 예약, 예약대장, 주말 불가, 실습 없는 기간 등)은 '예약 참고'로 들어가요. 예전 버전으로 넣은 기기는 다시 실행하면 고쳐져요 (목록 페이지 링크 → 기기 페이지, 매뉴얼의 위치 · 구분 · 담당 · 출처 줄 → 지우고 연락처는 '문의' 한 줄로, 정한 적 없는 교육 필요 · 예약 참고를 넣음. 손으로 고친 내용은 그대로).
9. (매뉴얼 파일 올리기를 쓸 때) 아래 [매뉴얼 파일 올리기 (Apps Script)](#매뉴얼-파일-올리기-apps-script)를 한 번 해요.

## 매뉴얼 파일 올리기 (Apps Script)

기기 수정 창의 **📤 파일 올리기**로 PDF · 동영상 같은 매뉴얼 파일을 내 구글 드라이브 `#공동기기` 폴더(그 안의 기기 이름 폴더)에 올리고, 보기 링크가 그 기기 매뉴얼에 바로 붙어요. 총관리자와 그 기기 담당자만 올릴 수 있어요.

- 앱 → [`tools/drive-upload.gs`](tools/drive-upload.gs)(내 계정으로 도는 Apps Script 웹 앱) → 드라이브. 웹 앱은 앱 로그인 토큰으로 Firestore를 읽어 총관리자 · 담당자인지 확인해요 (가짜 · 만료 토큰은 Firestore가 거절).
- 큰 동영상도 돼요: 앱이 16MB씩 나눠 보내고 드라이브의 이어 올리기에 차례로 붙여요. 올리는 동안 % 가 보여요.
- 올린 파일은 '링크가 있는 모든 사용자 보기'로 두어요. 드라이브 용량(무료 15GB)을 써요.
- 기기 수정 창에서 **앱으로 올린 파일**의 링크를 ✕로 빼고 저장하면, 확인 창을 거쳐 그 파일을 **드라이브 휴지통**으로 보내요 (30일 안에 되살릴 수 있어요). 직접 붙여 넣은 링크, 다른 기기에도 붙어 있는 파일, `#공동기기` 폴더 밖의 파일은 건드리지 않아요. 기기를 삭제할 때는 드라이브 파일이 그대로 남아요.

설정 (한 번):
1. [script.google.com](https://script.google.com)에서 **새 프로젝트**를 만들고 이름을 '공동기기 매뉴얼 올리기'로 해요.
2. `Code.gs` 내용을 지우고 [`tools/drive-upload.gs`](tools/drive-upload.gs) 내용을 붙여 넣고 저장해요. 맨 위 `FOLDER_ID`는 `#공동기기` 폴더로 들어 있어요 (폴더를 바꾸면 주소의 `folders/` 뒤를 넣어요).
3. **배포 → 새 배포** → 유형 **웹 앱** → 실행 사용자 **나**, 액세스 권한이 있는 사용자 **모든 사용자** → **배포**.
4. 권한 검토에서 내 계정을 고르고, 'Google에서 확인하지 않은 앱'이 나오면 **고급 → (프로젝트 이름)(으)로 이동 → 허용**해요 (내가 만든 스크립트예요. 드라이브와 외부 연결 권한).
5. 나온 **웹 앱 URL**(`…/exec`)을 [`js/firebase-config.js`](js/firebase-config.js)의 `manualUploadUrl`에 넣고 main에 올려요. 그러면 기기 수정 창에 **📤 파일 올리기**가 생겨요.

- `drive-upload.gs`를 고친 뒤에는 **배포 → 배포 관리 → ✎ → 버전: 새 버전 → 배포**를 해요 (주소는 그대로).
- 웹 앱 주소는 아무나 부를 수 있지만, 올리기는 앱의 총관리자 · 그 기기 담당자 토큰이 있어야 시작돼요.

## 로그인

- **Google로 로그인**: 학교 지메일, 개인 구글 계정.
- **구글 계정이 아닌 메일로 (학교 메일 등)**: 메일과 비밀번호로 계정을 만들면 그 메일로 인증 링크가 가요. 링크를 누른 뒤 '인증했어요'를 눌러야 가입 신청을 할 수 있어요 (남의 메일로 가입하지 못하게, 규칙에서도 확인). 비밀번호를 잊으면 '비밀번호를 잊었어요'로 다시 정해요. 메일이 안 오면 스팸함을 봐요.

## 데이터는 어디에

- 모든 데이터는 Firestore의 최상위 공유 컬렉션 여섯 개에 있어요. 여러 사람이 같은 데이터를 봐야 해서 `users/{uid}/…` 아래가 아니에요.

| 컬렉션 | 문서 하나 | 주요 필드 |
|---|---|---|
| `users/{uid}` | 사용자 | name, email, labId, labName, role(`pending` / `member` / `admin`), active, createdAt, approvedBy, approvedAt |
| `labs/{labId}` | 연구실 | name, order |
| `equipment/{equipId}` | 기기 | name, location, managers[uid], managerNames{uid: 이름}, requiresApproval, rules{slotMinutes, maxHours, maxDaysAhead, openFrom, openTo}, status(`ok` / `maintenance` / `broken`), statusNote, statusUntil, manual{body, links[{title, url, type(올린 파일의 종류)}]}, order, updatedAt |
| `bookings/{bookingId}` | 예약 | equipId, uid, userName, labId, start, end, purpose, status(`pending` / `approved` / `rejected` / `cancelled`), decidedBy, decidedAt, reason, createdAt, updatedAt |
| `logs/{bookingId}` | 사용일지 (예약 하나에 하나) | equipId, uid, labId, actualStart, actualEnd, note, problem, createdAt, updatedAt |
| `photos/{equipId}` | 기기 사진 (기기 하나에 하나) | src(앱에 들어 있는 사진 경로 `img/equip/…` 또는 앱에서 줄여 올린 사진의 data URL), by, updatedAt |

- 기기 사진은 Firebase Storage(지금은 유료 Blaze 요금제가 있어야 씀) 대신 Firestore에 둬요. 앱에서 올린 사진은 브라우저에서 긴 쪽 1024px JPEG로 줄여 문서 하나(1MB 제한)에 넣고, 동인동 기기 사진은 의대 홈페이지 사진을 줄여 앱 파일(`img/equip/`)로 넣어 두고 경로만 저장해요. 기기 목록과 따로 받아서 기기를 고쳐도 사진을 다시 받지 않아요.

- 시간은 Firestore Timestamp로 저장하고 화면은 서울 시간(Asia/Seoul)으로 보여 줘요.
- 예약에는 이름 · 연구실을, 기기에는 담당자 이름(managerNames)을 복사해 둬요. `users`는 본인과 총관리자만 읽을 수 있어서, 그리드와 기기 카드를 그릴 때 `users`를 읽지 않으려고요.
- 권한은 화면이 아니라 [`firestore.rules`](firestore.rules)에서 막아요. 로그인하지 않은 사람은 아무것도 못 읽고, 가입 대기 · 비활성 사용자는 연구실 목록과 자기 문서만 읽어요. 예약을 만들 때 규칙에서도 본인 · 이름 · 연구실, 승인 필요 여부에 맞는 상태, 점검 · 고장 기간, 1회 최대 시간, 며칠 앞까지를 확인해요. 예약끼리 겹치는지는 규칙으로 막을 수 없어요.
- 백업 파일(`equip-med-backup-날짜.json`)에는 이름 · 이메일이 들어 있어요. 저장소에는 올리지 마세요 (`.gitignore`에 들어 있어요).
- 이 브라우저에는 언어 · 테마 · 글씨 크기 · 마지막 탭 · 고른 기기만 `equip-med-prefs`(localStorage)에 저장해요. Firestore 기기 캐시는 같은 주소의 다른 앱과 나눠 쓰는 여러 탭 방식으로 열어요.

## 개발

- 빌드 없는 HTML/CSS/JS예요. `js/sync.js`만 ES 모듈이고 Firebase SDK(12.19.0)는 gstatic에서 불러와요.
- 로컬 서버: `powershell -NoProfile -ExecutionPolicy Bypass -File tools/serve.ps1` → http://localhost:8767/ (포트는 `PORT` 환경 변수로 바꿔요). Firebase 로그인을 로컬에서 쓰려면 승인된 도메인에 `localhost`도 넣어요.
- 아이콘: `tools/make-icons.ps1` (색은 HaLab 슬라이드 갤러리 크림슨 테마 단계).
- 새 js · css 파일을 만들면 `sw.js`의 `SHELL`에 꼭 더해요.
